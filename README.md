🚀 **My DevOps Learning Journey | Hands-on Learning with Git & GitHub**

As part of my continuous learning journey in Cloud and DevOps, I have been exploring Git and GitHub in depth and practising different commands through hands-on exercises.

I focused on understanding how Git helps developers manage source code, track changes, collaborate with team members, and maintain different versions of an application.

Here is a summary of what I have learned:

🔹 **1. Git & Version Control Fundamentals**
- Distributed Version Control System (DVCS)
- Git vs GitHub
- Repository, Remote, Origin and Commit
- Local and Remote Repositories
- HTTPS and SSH remote URLs

🔹 **2. Git Initialization & Basic Commands**
- `git init` – Initialize a Git repository
- `git config` – Configure username and email
- `git status` – Check repository status
- `git diff` – Identify changes in files
- `git add` – Move changes to the staging area
- `git commit` – Save changes in the local repository
- `git log` – View commit history
- `.gitignore` – Exclude unnecessary files from version control

🔹 **3. Understanding Git Workflow**

Learned the complete Git workflow:

- Working Directory
- Staging Area
- Local Repository
- Remote Repository

Understanding how changes move from the working directory to the remote repository using Git commands.

🔹 **4. Working with Remote Repositories**
- `git clone` – Clone an existing remote repository
- `git remote add origin <URL>` – Connect a local repository to a remote repository
- `git remote -v` – View remote repository URLs
- `git fetch` – Download remote changes without integrating them
- `git pull` – Fetch and integrate remote changes
- `git push` – Upload local commits to a remote repository

🔹 **5. Git Branching & Branching Strategies**

Learned how to develop new features without affecting the stable application code.

- Creating and switching branches
- Feature Branching Strategy
- GitFlow Workflow
- Main/Master, Develop, Feature, Release and Hotfix branches
- Pushing and deleting branches
- Renaming branches

🔹 **6. Git Merge & Rebase**

Explored different approaches to integrate changes between branches.

- `git merge <branch>` – Merge changes into the current branch
- `git rebase <base>` – Reapply commits onto another base
- `git rebase -i <base>` – Interactively modify commit history
- `git rebase --abort` – Abort an ongoing rebase
- `git rebase --continue` – Continue after resolving conflicts
- `git pull --rebase` – Fetch and rebase remote changes

Also understood the differences between Git Merge and Git Rebase, including commit history and their use cases.

🔹 **7. GitHub Collaboration**
- Creating Pull Requests (PR)
- Understanding Code Review
- Integrating feature branches into the main branch
- Collaborating with multiple developers

🔹 **8. Handling Git Conflicts**
- Identifying merge conflicts
- Understanding why conflicts occur
- Resolving conflicts manually
- Staging resolved files
- Completing merge or rebase operations

🔹 **9. Advanced Git Concepts**
- `git stash` – Temporarily save uncommitted changes
- `git stash pop` – Restore stashed changes
- `git cherry-pick` – Apply a specific commit to another branch
- Understanding commit history and branch integration

💡 **Key Takeaways:**

Through hands-on practice, I gained a better understanding of how Git supports:

✅ Source Code Management  
✅ Version Control and History Tracking  
✅ Team Collaboration  
✅ Feature Development and Branch Management  
✅ Code Integration and Conflict Resolution  
✅ Collaborative Software Development Workflows  

**Real-world DevOps Use Case:**

Git and GitHub play a critical role in CI/CD pipelines, where developers push code changes, collaborate through pull requests, and integrate approved changes for automated build, test, and deployment processes.

I'm continuing to strengthen my practical knowledge by working on real-world scenarios and exploring more DevOps tools.
